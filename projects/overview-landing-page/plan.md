# Implementation Plan: Design Partner Page

> Derived from `spec.md`. Phases, deliverables, and the acceptance gate for
> each. Generated by `project-pipeline` on 2026-10-21.

## Shape of the work

Four phases. Almost every part has a working model in the codebase, so the
order follows dependencies, not risk: assets first, then the server side
that stores and sends an application, then the page that uses both, then the
redirects and the preview check that connect it to the carousel and the
postcard.

The server side comes before the form so the form can be tested against a
real route from its first run.

## Phase 0: Assets

**Deliverables**

- Nine slide images rendered from the approved carousel source, PNG or WebP
- The carousel PDF as `spaarke-overview.pdf`
- An Open Graph image, 1200 by 630, cut from the cover
- All in `public/design-partners/`; no HTML source in the repo

**Gate.** The files exist, the images total under 2 MB, and the PDF opens
with nine pages and the title "Spaarke Overview".

## Phase 1: Server side

**Deliverables**

- `saveDesignPartnerApplication()` in `src/lib/storage.ts`
- `sendDesignPartnerNotification()` in `src/lib/email.ts`
- `POST /api/design-partners`, modelled on the early-release route
- A design partner section in the daily report

**Gate.** A local request with valid data returns 200; invalid data returns
400 with field errors; a missing captcha token returns 403; the rate limit
returns 429. Storage and email log a skip, not a crash, when their settings
are absent. Typecheck passes.

**Risk this retires.** A submission that looks successful to the visitor but
reaches nobody. The route must await storage and email with the same
timeout handling as the early-release route.

## Phase 2: The page

**Deliverables**

- `src/app/design-partners/page.tsx`: hero, contribute and receive lists,
  application section, further reading, metadata
- The slide strip with the download link and the "Overview Download" event
- `DesignPartnerForm.tsx` with validation, captcha, attribution, consent,
  and the "Design Partner Submit" event
- The two event names in `src/types/plausible.d.ts`
- The sitemap entry

**Gate.** The page builds statically, reads correctly at desktop and at
360 px with no horizontal scroll, every slide has alt text, the copy passes
voice lint, and a local submission reaches the route.

## Phase 3: Connections and preview

**Deliverables**

- `/advisory-group` permanent redirect and the `/go/more-info-1` destination
  change in `next.config.ts`
- The contact form reason renamed, with the pointer to the page
- A pull request and a test on the Static Web Apps preview

**Gate.** Every success criterion in `spec.md` that can be checked on the
preview passes: a test application lands in the table and at
contactus@spaarke.com, both redirects keep their query strings, the PDF
downloads, and both Plausible events fire.

## Dependencies between phases

Phase 2's strip needs phase 0's images. Phase 2's form needs phase 1's route.
Phase 3 needs both. Phase 1 can run in parallel with phase 0.

## Risks

| Risk | Mitigation |
|---|---|
| Preview environment lacks the storage or SendGrid settings | Check SWA app settings for the preview before the test submission |
| Slide images too heavy for phones | WebP above 2 MB in total, lazy loading below the hero |
| The carousel source leaks into the public repo | Copy only rendered images and the PDF; check the PR file list |
| A page copy edit breaks the voice rules | Voice lint in the phase 2 gate |
